> 不要把 Vibe Coding 當成一次性的產生器，而是把它設計成可重複使用、可編輯、可持續演化的工作流。

- 後來進一步把這個流程封裝成 Agent Skill，讓新需求可快速重複使用

> **重點不是哪一款 AI 最強**
> 教學目標從來不是押寶單一工具，而是建立「多個 AI Agent 交替使用」的能力。
>

### 🧠 為什麼我要刻意輪流使用不同 AI 工具
- 某個 AI 工具被捧紅後，很可能很快就被新的工具取代
- 真正重要的是理解怎麼解決痛點，而不是記住某個產品名稱
- 工具能力差異往往沒有想像中那麼大，但價格、定位與節奏會持續改變
- 不建議為了一時折扣就綁年費，因為「最好用的組合」會一直更新

# 終端機實戰：安裝 Codex 並生成第一版網頁
> 先讓流程跑起來，再逐步理解每個環節的目的與限制。

## 開始前的準備

### 🗂️ 先給 AI Agent 一個明確工作區
- 建立一個空資料夾，作為這次生成講義網站的專案空間
- 在編輯器中使用 `Open Folder` 開啟，或直接拖曳資料夾進來
- 這麼做的目的，是讓 AI 在清楚邊界內產出與修改檔案

### 🔍 確認 Node.js 是否可用
```prompt [label="檢查 Node.js 版本"]
node -v
```

- 如果能看到版本號，代表可直接進行後續步驟
- 如果出現找不到指令的錯誤，就需要先安裝 Node.js
- 實務上建議搭配 NVM 管理版本，後續升級與切換會比較輕鬆

### 🛠️ 用 NVM 安裝 Node.js
```prompt [label="macOS 安裝 NVM"]
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.4/install.sh | bash
```

```prompt [label="檢查 NVM 與安裝 LTS 版 Node.js"]
nvm -v
nvm install --lts
node -v
```

- Mac 可用官方安裝腳本處理
- Windows 則需下載 `nvm-windows` 的安裝程式
- 安裝完後重新開一個終端機視窗，再檢查 `nvm -v`

## 安裝 Codex 並登入

### 🚀 全域安裝
```prompt [label="安裝 Codex"]
npm i -g @openai/codex
```

### 🔐 三種登入方式
[flow]
1. 直接用 ChatGPT 帳號登入：最推薦，流程也最直覺
2. 用裝置代碼登入：適合沒有瀏覽器介面的 VM 或遠端環境
3. 輸入 OpenAI API Key：依實際用量計費，需自行控管成本
[/flow]

[tags]
- [green] ChatGPT 帳號登入最適合一般使用者
- [orange] 裝置代碼登入前，要先在 ChatGPT 安全設定開啟對應選項
- [purple] API Key 方案彈性高，但若沒控管額度容易超支
[/tags]

### 🧭 進入 Codex 後會看到什麼
- 第一次進入會先詢問是否信任目前資料夾，必須選 `Yes` 才能繼續
- 接著出現的輸入框，本質上就像熟悉的 AI 對話視窗
- 你可以直接用自然語言描述需求，讓 AI 在專案裡生成檔案

## 用 Prompt 生成第一版講義網站

### ✍️ 提示詞示範
```prompt [label="生成講義網站的 Prompt"]
請扮演熟悉 AI 主題授課的講師，以「Agent Skills」為主題設計講義
講義用純 html 網頁（CSS/JS 都放裡面）呈現
日系風格的設計感，部分文字與背景可以搭配適當的漸層
開頭會根據內容呈現標題，然後下面有發人深省的標語
會根據不同層級與意圖呈現對應的區塊（ex: 大小標題、陳述、列點、流程）
最後放上社群連結鼓勵大家訂閱（FB/YouTube/Medium）
側邊欄會有對應的目錄，方便跳轉到對應位置
```

### 🧩 這段 Prompt 的設計重點
- 目標明確：指定只生成單一 HTML，降低部署與維護成本
- 風格清楚：要求日系設計感與漸層語言，讓畫面更接近期待
- 架構完整：明講開頭、分層內容、收尾社群 CTA 與側邊欄目錄

> **第一版能用，不代表後續好改**
> 只要需求開始進入細節調整，單純依賴 AI 反覆改 HTML，很快就會碰到控制力不足的問題。

# 關鍵轉折：從一次性 HTML 走向可維護模板
> 真正能落地的，不是「生成得很快」，而是「生成後還能輕鬆調整」。

## 為什麼直接改 HTML 很痛苦

### 😵 兩種常見做法都不理想
- 繼續和 AI 對話修細節：結果隨機性高，還可能改壞原本正常的區塊
- 自己手動改 HTML：就算有工程背景，也很容易被版型細節拖住
- 若調整成本過高，再快的初稿產生速度都很難真的進入日常工作流

### 🧱 解法：建立模板，而不是每次從零生成
- 把穩定的視覺、版型、互動先收斂成一個固定模板
- 每次只替換內容，而不是重做整份網站
- 這讓講義、文件、簡報等重複性內容都能快速產出一致品質

## 把 HTML 逆向成 Markdown 工作流

### 📝 第二段 Prompt 的目標
```prompt [label="把 HTML 工作流轉成 Markdown 模板"]
我希望剛剛生成出來的網頁，是可以透過 Markdown 格式編輯內容的
請幫我將網頁結構拆解（列點、步驟、圖片、表格、註解）、分層次（大標、中標、小標），並以常見的 Markdown 語法來設計規則
最後建立一個腳本，我只要編輯 Makdown 文件，網頁的 HTML 就會及時改變
操作方式寫在 README.md 文件中，並建立 package.json
```

### 🔧 這個要求其實在做四件事
[flow]
1. 把最終產物 HTML 背後的內容結構抽離出來
2. 用容易維護的 Markdown 當成主要編輯介面
3. 建立腳本，讓 Markdown 變動時可以重新產生 HTML
4. 補上 README 與 package.json，讓整個流程可交接、可重跑
[/flow]

### ✅ 為什麼 Markdown 是比較好的控制層
- 內容與版型分離，修改時更容易聚焦在訊息本身
- 語法簡單，大多數人都能快速上手
- 之後若要重新排版，只要更新模板與腳本，不必重寫全部內容

# 進一步封裝：把整套流程做成 Agent Skill
> 如果某個流程會反覆出現，就值得把它從「一次的操作」提升為「可重複的能力」。

## Agent Skill 的設計目標

### 🧭 我給 AI 的需求方向
```prompt [label="建立 Agent Skill 的需求"]
根據下面需求在「.agents」資料夾建立 Skill：
- 參考模板：根據剛剛腳本設計的規格，建立明確的 Markdown 使用規範
- 觸發時機：使用者提供初步想法想建立網頁時，會觸發這個 Skill
- 執行順序：這個 Skill 會先深入研究輸入的主題，再根據規範設計對應的 Markdown 文件；最後把 Markdown 文件透過腳本生成 html
- 特別提醒：預計會有多個主題，所以觸發時，請先建立新的資料夾，裡面存放新生成的 Markdown 與 HTML 檔案；並且建立獨立的 scripts 與 references 資料夾，確保可單獨執行
```

### 🗃️ Skill 建立後的結果
- `.agents/SKILL.md`：定義名稱、觸發時機與工作流程
- `references/`：放 Markdown 格式規則與範例
- `scripts/`：存放 build、dev、產圖等腳本
- 新主題來時，只要提供初步需求，就能建立獨立課程資料夾並生成網頁

### 🧪 驗證方式
- 先讓 AI 依規範產出初版內容
- 執行 `npm run dev` 開啟預覽頁
- 回頭修改 Markdown，確認 HTML 是否會即時反映變化

> **這裡的核心不是炫技，而是建立穩定流程**
> 當輸入格式、輸出模板、建置腳本都穩定下來，AI 才真正從聊天工具升級成可依賴的生產力系統。

# 另一種入口：在編輯器中安裝 Codex 外掛
> 終端機很強，但圖形介面對初學者通常更友善。

## 安裝與登入流程

### 🧩 在 Antigravity 安裝外掛
- 打開左側 `Extensions`
- 搜尋 `chatgpt`
- 第一個就是要安裝的外掛
- 若搜尋不到，可直接輸入 `antigravity:extension/openai.chatgpt` 開啟頁面

### 🔐 登入後的使用體驗
- 打開任一檔案，點上方 ChatGPT 圖示即可進入對話面板
- 支援用 ChatGPT 帳號登入，也可切換成 API Key 模式
- 如果只是想快速體驗，帳號登入通常最順手

## 介面上有哪些值得認識的能力

### 🖱️ 比終端機更適合新手的地方
- 可以直接切換 GPT 模型與思考深度
- 開啟滑鼠游標感知後，AI 能知道你目前選中的區域與打開的檔案
- 輸入 `/` 還能看到更多進階設定與操作指令
- 想做更完整的初始化規劃時，也可以打開 Plan Mode

## 最後想留下的提醒

[summary]
- 🌱 **先從實際痛點出發** | 講義網站只是案例，真正重點是把重複性工作抽象成流程
- 🧱 **模板比一次性成品更有價值** | 可維護、可調整、可重複使用，才是真正能進入工作現場的成果
- 🤖 **Agent Skill 是流程封裝器** | 它把研究主題、整理內容、生成網頁這些步驟固定成可重跑能力
- 🧭 **工具會變，方法論要留下** | 不要只追逐單一 AI，而是培養跨工具解題與設計系統的能力
[/summary]
